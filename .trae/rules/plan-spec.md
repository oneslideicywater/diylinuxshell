## 决策规范

- 碰到需要管理员权限的时候，不要自己运行，而是提示我来操作。
- `npm run package:win` 由我来运行。

## 测试规范

e2e测试应该有一个总入口，可以一键执行所有测试用例，每次新增测试用例后，需要更新总入口的测试用例列表。

e2e测试应该维持一个README.md文件，记录所有测试用例的路径和描述。

## 代码规范

- 注意类型安全，变量声明要显示声明类型。
- 注意测试文件按测试功能放到不同目录，按照最佳实践组织。
- 按照xshell行为标准来组织逻辑。
- 编写必要的注释

## bug记录

所有bug记录放入/docs/bugs目录下，文件命名遵循BUG-000-描述.md格式。

bug处理记录规范：记录更改前和更改、记录复现步骤、原因、解决方法、相关测试用例。

### 开发流程

1. 新增功能、修改功能、修复bug，查看phase对应prd和plan，更新两个文档。
2. 完成第1步，然后再编写代码、测试用例、运行测试用例验证、清理测试用例产生的数据，防止干扰下次测试。
3. 完成第2步后，更新plan、prd文档、更新bug记录
4. git 提交代码
