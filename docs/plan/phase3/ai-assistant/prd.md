## 二、功能概述

### 2.1 模块定位

AI 助理是一个智能化的服务器管理助手，集成 LLM（大语言模型）能力，通过自然语言交互帮助用户更高效地管理 Linux 服务器。

### 2.2 核心能力

- **LLM 提供商管理**：独立的模型对接模块，支持切换 GLM/豆包/Qwen兼容接口等大模型，在设置页面配置连接参数，运行时热切换
- **终端输出智能分析**：读取并分析终端输出内容本身，帮助用户理解日志、错误信息、命令结果等；支持右键菜单分析当前终端输出或选中特定文本行进行分析
- **工作留痕**：将终端输出内容转换为图片，用于工作记录、问题汇报、文档归档；支持对话指令触发截图、右键菜单截图、选区截图
- **智能对话交互**：Chat 对话界面、流式输出、Markdown 渲染（代码块可发送到终端）、本地知识库（LLM 自动维护、自动索引、自动注入上下文）
- **智能文件操作**：根据用户自然语言指令，自动执行 SFTP 文件上传、下载、编辑等操作
- **会话管理自动化**：通过自然语言快速创建、配置 SSH 会话连接
- **组合式任务执行**：理解用户复杂需求，自动拆解并执行多步骤任务流程

## 三、功能详细说明

### 3.1 终端输出分析

#### 3.1.1 功能描述

读取终端输出内容，调用 AI 帮助用户分析和理解输出本身。适用于日志查看（如 `tail -f /var/log/messages`）、命令结果解读、错误信息排查等场景。

#### 3.1.2 功能点

| 序号 | 功能点 | 描述 | 优先级 |
|------|--------|------|--------|
| 3.1.1 | 输出数据捕获 | 获取当前终端缓冲区或选中区域的文本内容 | P0 |
| 3.1.2 | ANSI 转义过滤 | 过滤终端 ANSI 转义序列，提取纯文本内容 | P0 |
| 3.1.3 | 右键菜单集成 | 终端右键菜单提供"分析当前输出"和"分析选中文本"入口 | P0 |
| 3.1.4 | 输出内容解析 | AI 解读日志含义、解释错误原因、总结命令结果 | P0 |

#### 3.1.3 触发方式

**方式一：右键菜单分析当前输出**
```
用户在终端区域右键 → 选择「AI 分析当前输出」→ AI 分析整个终端可见内容

适用场景：
- 执行完一组命令后，需要整体了解输出含义
- 查看日志文件（如 tail -f /var/log/messages）后，需要 AI 帮助解读
- 排查问题时，执行了多个诊断命令，需要综合分析输出结果

数据范围：
- 发送当前终端组件中的全部输出内容（非仅可视区域）
- 最大发送行数由设置中「AI 分析最大行数」控制，上限 10000 行
- 超过限制时优先发送最新的 N 行内容，并提示用户已截断
```

**方式二：选中文本行分析**
```
用户选中终端中若干行输出 → 右键选择「AI 分析选中文本」→ AI 仅分析选中部分
适用场景：只关注某段错误日志或特定命令的输出
```

**方式三：对话指令**
```
用户在 AI 对话框输入："帮我看看刚才终端输出的错误是什么意思"
AI 自动获取关联终端的最新输出内容进行分析（同样受最大行数限制）
```

**场景 1：日志分析**

用户选中以下输出并请求分析：

├─────────────────────────────────────┤

│                                      │

#### 3.3.3 Markdown 渲染增强

AI 输出以 Markdown 格式展示，其中**代码块**具备交互能力：

**代码块交互功能：**
- 每个代码块右上角显示操作按钮：**「复制」** **「发送到终端」**
- 点击「复制」将代码内容复制到系统剪贴板
- 点击「发送到终端」将代码内容直接写入当前关联的 SSH 终端并执行
- 支持多行命令，按行逐条发送
- 发送前弹出确认提示，防止误操作（可在设置中关闭确认）

**代码块识别规则：**
- AI 输出的 Markdown 中，`bash`、`shell`、`sh`、`cmd`、`terminal`、无语言标记的代码块均视为可执行命令
- `json`、`python`、`yaml` 等非 shell 类语言仅提供「复制」按钮，不显示「发送到终端」

**UI 示例：**
```

│ systemctl status nginx                      │

#### 3.3.4 本地知识库

由大模型**自动维护**的本地知识库，AI 在对话过程中自动提取、索引、更新知识条目，无需用户手动管理。每次对话时自动检索相关知识注入上下文，让 AI 越用越懂你的服务器环境。

**核心原则：LLM 自主维护**
- 知识库的**增删改查全部由 LLM 负责**，用户无需手动操作
- 每次对话结束后（或用户确认后），LLM 自动判断本次对话是否有值得沉淀的内容
- LLM 自动为知识条目生成标题、标签、摘要，并建立索引

**知识库核心能力：**

| 能力 | 说明 |
|------|------|
| **自动提取** | 对话中产生有价值的内容（排查结论、解决方案、配置要点、环境特征）时，LLM 自动提取并入库 |
| **自动索引** | 每条知识自动生成关键词索引和语义标签，支持精准检索 |
| **自动去重** | 相似内容自动合并或关联，避免冗余存储 |
| **自动注入** | 每次发起对话时，根据当前问题自动检索匹配的知识条目，拼接为 System Prompt 前缀 |
| **自动过期** | 过时的知识（如已修复的问题结论、已变更的配置）可被 LLM 标记降权或清理 |

**知识条目结构：**

| 字段 | 说明 | 来源 |
|------|------|------|
| 标题 | 简短描述（如"nginx 端口冲突解决"） | LLM 自动生成 |
| 内容 | 保存的精华文本（Markdown 格式） | LLM 从对话中提取 |
| 关联会话 | 来源的 SSH 会话 ID | 系统自动记录 |
| 标签 | 语义标签（如 `nginx`、`故障排查`、`性能优化`） | LLM 自动标注 |
| 关键词索引 | 用于检索的关键词列表 | LLM 自动生成 |
| 创建/更新时间 | 条目的创建和最后更新时间 | 系统自动记录 |
| 引用计数 | 被检索命中的次数，用于评估价值 | 系统自动统计 |
| 状态 | active / deprecated / archived | LLM 自动维护 |

**工作流程：**

```
┌─────────────────────────────────────────────────────┐
│                   对话进行中                          │
│                                                      │
│  用户提问 → AI 回答 → 用户确认问题解决                │
│                      ↓                               │
│              【后台触发】LLM 自检：                    │
│              "本次对话是否有值得保存的经验？"           │
│                      ↓                               │
│         ┌──── 是 ──→ 提取精华 → 生成标题/标签/索引    │
│         │               ↓                            │
│         │        写入本地知识库（加密存储）             │
│         │                                            │
│         └──── 否 → 本次无新增知识                     │
│                                                      │
└─────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────┐
│                 下次对话时                            │
│                                                      │
│  用户输入新问题                                       │
│      ↓                                               │
│  系统将问题发送给 LLM 进行**语义检索**                │
│      ↓                                               │
│  LLM 从知识库中匹配相关条目（基于索引 + 语义相似度）   │
│      ↓                                               │
│  将命中条目作为上下文前缀注入本次请求                  │
│      ↓                                               │
│  LLM 结合历史经验 + 当前问题生成更精准的回答           │
│                                                      │
└─────────────────────────────────────────────────────┘
```

**检索与注入机制：**
- **双重检索**：先通过关键词索引快速初筛，再由 LLM 做语义相关性排序
- **智能截断**：当匹配条目过多时，按相关性和引用优先级自动裁剪，控制 Token 消耗
- **会话感知**：优先检索与当前关联会话相关的知识，再补充全局通用知识

**存储位置：**
- 数据文件：`%APPDATA%/diy-linux-shell/knowledge-base.json`
- 加密存储，使用项目已有的 CryptoService
- 索引文件：同目录下 `knowledge-base-index.json`（加速检索）
- 支持导出/导入知识库数据（用于备份或多设备同步）

**设置项：**
| 设置项 | 说明 | 默认值 |
|--------|------|--------|
| 知识库开关 | 是否启用本地知识库功能 | 开启 |
| 自动提取模式 | `auto`(全自动) / `confirm`(每次提示确认) / `off`(关闭) | auto |
| 最大注入条数 | 单次对话最多注入多少条知识记录 | 5 条 |
| 最大知识库容量 | 上限条数，超出后 LLM 自动清理低价值条目 | 500 条 |

#### 3.6.3 执行流程

```
用户输入自然语言需求
    ↓
LLM 分析需求，理解意图
    ↓
LLM 动态拆解为有序的命令步骤列表
    ↓
展示步骤计划给用户确认
    ↓ 用户确认
逐条发送命令到终端执行
    ↓ 收集每步输出

    ↓ 全部完成
LLM 汇总所有步骤输出，生成任务报告
```

### 3.7 LLM 提供商管理

#### 3.7.1 功能描述

独立的 LLM 对接模块，支持切换不同的大模型提供商，用户可在设置页面配置各提供商的连接参数。

#### 3.7.2 功能点

| 序号 | 功能点 | 描述 | 优先级 |
|------|--------|------|--------|
| 3.7.1 | 多提供商支持 | 支持 OpenAI、Anthropic Claude、Ollama 本地模型等 | P0 |
| 3.7.2 | 兼容接口支持 | 支持任何 OpenAI API 兼容的第三方接口（如 DeepSeek、通义千问等） | P0 |
| 3.7.3 | 提供商配置管理 | 在设置页面中添加/编辑/删除/切换 LLM 提供商配置 | P0 |
| 3.7.4 | 模型选择 | 每个提供商下可选择具体模型（如 gpt-4o、claude-3.5-sonnet 等） | P0 |
| 3.7.5 | 连接测试 | 配置保存前可测试连通性，验证 API Key 有效性 | P0 |
| 3.7.6 | 热切换 | 运行时无需重启即可切换 LLM 提供商 | P1 |

#### 3.7.3 支持的提供商类型

| 类型 | 说明 | 示例 | 优先级 |
|------|------|------|--------|
| 兼容接口（国内） | OpenAI API 兼容格式的国产大模型，**优先对接** | DeepSeek、通义千问(Qwen)、智谱 GLM、豆包(Doubao)、百度文心一言、Moonshot | **P0（首选）** |
| Ollama | 本地部署的开源模型 | Qwen2.5、DeepSeek-R1、Llama 3、GLM-4 | P0 |
| OpenAI | 官方 OpenAI API（需自行解决网络问题） | GPT-4o, GPT-4o-mini, o1 | P2 |
| Anthropic | Anthropic Claude 系列（需自行解决网络问题） | Claude 3.5 Sonnet, Claude 3 Opus | P2 |

> **说明**：Phase 3 开发阶段**优先对接国内可用的 LLM 接口**（兼容接口类型），确保开箱即用。OpenAI/Anthropic 等海外模型作为扩展能力，后续版本迭代支持。

#### 3.7.4 设置页面配置项

每个提供商配置包含以下字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 提供商名称 | 文本 | 是 | 用户自定义名称，如"OpenAI 官方"、"本地 Ollama" |
| 提供商类型 | 选择 | 是 | 从支持的类型列表中选择 |
| API 端点地址 | URL | 是 | API 接口地址（本地模型填 http://localhost:11434） |
| API Key | 密码 | 视类型而定 | 加密存储，本地模型可不填 |
| 模型名称 | 选择/文本 | 是 | 要使用的具体模型名称 |
| 最大 Token 数 | 数字 | 否 | 单次请求最大 Token 上限，默认 8192 |
| 温度参数 | 滑块 | 否 | 控制输出随机性，默认 0.7，范围 0-2 |
| 是否启用 | 开关 | - | 设为当前活跃提供商 |

#### 3.7.5 切换流程

```
设置页面 → AI 助理 → LLM 提供商
    │
    ├─ 添加新提供商
    │   └─ 填写配置 → 连接测试 → 保存
    │
    ├─ 编辑已有提供商
    │   └─ 修改参数 → 连接测试 → 保存
    │
    ├─ 切换当前提供商
    │   └─ 选择目标提供商 → 设为启用 → 即时生效
    │
    └─ 删除提供商
        └─ 确认删除（不可删除当前启用的提供商）
```

#### 3.7.6 安全要求

- API Key 采用加密存储（使用项目已有的 CryptoService）
- 设置页面中 API Key 默认脱敏显示，点击可查看/复制
- 导出配置时不包含明文 API Key
- 通过 IPC 传输时 API Key 需加密

## 四、技术要求

### 4.1 LLM 集成

| 要求项 | 说明 |
|--------|------|
| 架构设计 | 采用 Provider 模式，通过统一接口适配不同 LLM 提供商（详见 3.7） |
| API 支持 | 支持 OpenAI API 及兼容接口格式 |
| 本地模型 | 支持 Ollama 等本地模型部署 |
| 流式输出 | 必须支持 SSE 流式响应 |
| Token 控制 | 上下文窗口管理和自动裁剪 |

### 4.2 安全要求

| 要求项 | 说明 |
|--------|------|
| 敏感过滤 | 密码、API Key、私钥等敏感信息必须脱敏处理 |
| 加密存储 | API Key 等配置加密存储 |
| 权限控制 | 危险操作必须用户确认 |
| 审计日志 | 记录所有 AI 操作日志 |

### 4.3 性能要求

| 指标 | 要求 |
|------|------|
| 首响延迟 | < 2 秒 |
| 流式输出延迟 | < 500ms（首字） |
| 上下文加载 | < 1 秒 |
| 离线降级 | LLM 不可用时，其他功能不受影响 |

## 六、验收标准

### 6.1 功能验收

- [ ] 能够通过对话框与用户进行自然语言交互
- [ ] 支持流式输出，响应及时无明显延迟
- [ ] 能够正确识别用户意图（文件操作、会话管理、信息查询等）
- [ ] 能够实时捕获并分析终端输出内容
- [ ] 分析结果准确，能够正确提取服务器状态信息
- [ ] 敏感信息过滤机制正常工作，密码、API Key 等不会被发送到 LLM
- [ ] 能够根据自然语言指令执行 SFTP 文件操作（上传/下载/列表）
- [ ] 文件操作前需要用户确认，防止误操作
- [ ] 能够通过对话快速创建 SSH 会话配置
- [ ] 组合式任务能够正确拆解并按步骤执行
- [ ] 任务执行过程有进度反馈
- [ ] 支持多轮对话，能够记住上下文
- [ ] 上下文窗口管理正常，超长对话自动裁剪历史
- [ ] 支持 OpenAI API 及兼容接口配置
- [ ] API Key 安全存储，加密保存
- [ ] 网络异常时有合理的错误提示
- [ ] LLM 服务不可用时降级处理，不影响其他功能使用

### 6.2 流程验收

- [ ] AI 对话 → 意图识别 → 操作执行 → 结果反馈，流程闭环
- [ ] 终端输出捕获 → 内容分析 → 智能建议展示，流程闭环
- [ ] 用户输入 → 任务拆解 → 分步执行 → 报告生成，流程闭环

### 6.3 异常验收

- [ ] API Key 未配置时有清晰引导
- [ ] 网络超时有重试机制和友好提示
- [ ] LLM 返回异常内容有容错处理
- [ ] 流式中断时能够恢复或重新生成

## 七、风险与应对

| 风险 | 影响 | 应对措施 |
|------|------|----------|
| LLM API 成本过高 | 运营成本增加 | 支持本地模型；Token 使用优化；设置用量限制 |
| LLM 响应质量不稳定 | 用户体验差 | Prompt 工程优化；结果审核机制 |
| 敏感信息泄露 | 安全风险 | 强制脱敏；审计日志；权限控制 |
| 离线环境无法使用 | 功能不可用 | 降级方案；离线模式提示 |
