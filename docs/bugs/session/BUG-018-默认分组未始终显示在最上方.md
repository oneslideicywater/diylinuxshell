# BUG-018: 默认分组未始终显示在最上方

## 问题描述

默认分组虽然存在，但没有始终显示在分组列表的最上方。当用户创建新的分组后，新分组可能显示在默认分组之前，这不符合 PRD 的要求。

**后续发现**: 当没有会话但有分组时，分组列表完全不显示，页面显示"暂无会话"的空状态。

## 问题原因

**问题 1 - 排序问题**: 分组列表按照 `order` 字段（创建时间）排序，导致后创建的分组可能排在默认分组前面。

**问题 2 - 空状态条件问题**: 空状态的条件为 `v-else-if="sessions.length === 0"`，当会话列表为空时，即使有分组也会显示空状态，导致分组列表被跳过不渲染。

## 复现步骤

1. 启动应用
2. 确认默认分组存在
3. 创建一个新的分组
4. 观察分组列表，发现新分组可能显示在默认分组之前

**预期结果**: 默认分组始终显示在分组列表最上方
**实际结果**: 分组按创建时间排序，默认分组可能不在最上方

## 修复方案

### 修复 1 - 默认分组排序

修改 `src/renderer/src/components/session/SessionList.vue` 中的 `sessionGroups` computed 属性，特殊处理默认分组的排序：

#### 代码变更

**修改前：**
```typescript
// 会话分组列表
const sessionGroups = computed(() => {
  return sessionStore.sessionGroups
})
```

**修改后：**
```typescript
// 会话分组列表
const sessionGroups = computed(() => {
  const groups = sessionStore.sessionGroups
  
  // 找到默认分组
  const defaultGroup = groups.find(g => g.name === '默认分组')
  
  if (!defaultGroup) {
    // 没有默认分组，直接返回所有分组（按 order 排序）
    return [...groups].sort((a, b) => a.order - b.order)
  }
  
  // 过滤出非默认分组
  const otherGroups = groups.filter(g => g.name !== '默认分组')
  
  // 默认分组排在最前面，其他分组按 order 排序
  return [defaultGroup, ...otherGroups.sort((a, b) => a.order - b.order)]
})
```

#### 实现逻辑

1. 从 `sessionStore.sessionGroups` 中获取所有分组
2. 查找名为"默认分组"的分组
3. 如果找不到默认分组，直接返回所有分组（按 `order` 排序）
4. 如果找到默认分组：
   - 过滤出非默认分组
   - 将默认分组放在数组第一位
   - 其他分组按 `order` 排序后追加到默认分组后面

### 修复 2 - 空状态条件

修改 `SessionList.vue` 模板中的空状态显示条件：

**修改前：**
```vue
<!-- 空状态 -->
<div v-else-if="sessions.length === 0" class="empty-state">
  <p>暂无会话</p>
  <p class="hint">点击上方 + 按钮创建新会话</p>
</div>
```

**修改后：**
```vue
<!-- 空状态：既没有会话也没有分组时显示 -->
<div v-else-if="sessions.length === 0 && sessionGroups.length === 0" class="empty-state">
  <p>暂无会话</p>
  <p class="hint">点击上方 + 按钮创建新会话</p>
</div>
```

#### 修复逻辑

1. 原条件 `sessions.length === 0` 在会话列表为空时就会显示空状态
2. 新条件 `sessions.length === 0 && sessionGroups.length === 0` 确保只有在既没有会话也没有分组时才显示空状态
3. 这样即使没有会话，分组列表也会正常渲染和显示
