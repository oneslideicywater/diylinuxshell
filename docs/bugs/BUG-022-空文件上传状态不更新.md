# BUG-022：上传文件状态不更新

## Bug 描述

**问题现象**：
- 上传文件夹时，某些文件上传完成后，UI 界面中该文件的状态一直显示"等待中"
- 文件实际上已经成功上传到远程服务器
- 只有状态没有更新，进度回调没有触发

**影响范围**：
- 空文件（0 字节）
- 某些非空文件（如果最后一个 data 事件的回调执行滞后）

## 根本原因

在 `src/main/services/sftp.ts` 的 `uploadFile` 函数中：

1. **进度回调触发位置不当**：
   - 原代码只在 `readStream.on('data', ...)` 事件的回调中触发进度更新
   - 对于空文件（0 字节），`readStream` 不会触发 `data` 事件，直接触发 `end` 事件
   - 导致空文件上传完成后，没有触发任何进度回调

2. **`end` 事件缺少最终回调**：
   - 原代码只在 `fileSize === 0` 时才在 `end` 事件中触发进度回调
   - 但对于非空文件，如果最后一个 `data` 事件的异步写入回调执行滞后，可能在进度回调之前就进入了 `end` 事件
   - 导致渲染进程收不到 100% 完成的进度事件

3. **进度回调条件判断**：
   ```typescript
   if (onProgress && fileSize > 0) {
     onProgress((uploadedBytes / fileSize) * 100)
   }
   ```
   - 当 `fileSize === 0` 时，即使有数据写入也不会触发进度回调

## 修复方案

在 `readStream.on('end', ...)` 回调中添加最终的进度通知，对所有文件都触发完成回调：

```typescript
readStream.on('end', () => {
  try {
    this.sftpHandle.close(handle)
  } catch (closeErr) {
    // 忽略关闭错误
  }
  // 确保在文件上传完成时触发最后一次进度回调
  if (onProgress) {
    const now = Date.now()
    const timeDiff = (now - lastUpdateTime) / 1000 // 转换为秒
    const bytesDiff = uploadedBytes - lastUploadedBytes
    const speed = timeDiff > 0 ? bytesDiff / timeDiff : 0
    onProgress(100, fileSize, uploadedBytes, speed)
  }
  resolve()
})
```

## 修复效果

修复后：
1. ✅ 空文件上传完成后会触发 `onProgress(100, 0, 0, 0)` 回调
2. ✅ 非空文件上传完成后会触发 `onProgress(100, fileSize, uploadedBytes, speed)` 回调
3. ✅ 渲染进程能收到完成事件并更新节点状态
4. ✅ 所有文件（无论大小）上传完成后都会正确更新状态
5. ✅ 父节点状态能正确递归更新为"已完成"
