# BUG-001: 默认分组不显示

## 问题描述

应用启动后，目录树中没有显示"默认分组"，导致用户无法看到和管理会话。

## 问题原因

`createDefaultGroup()` 函数的逻辑是检查 `groups.length === 0`，这意味着：
- 只有在**没有任何分组**时才会创建默认分组
- 如果用户之前已经创建了其他分组，但没有默认分组，就不会创建

## 复现步骤

1. 启动应用
2. 创建一个新分组
3. 删除默认分组（如果之前存在）
4. 重启应用
5. 观察目录树，发现没有显示默认分组

## 修复方案

修改 `src/main/index.ts` 中的 `createDefaultGroup()` 函数：
- 改为检查是否存在名为"默认分组"的分组
- 如果不存在"默认分组"，则创建它
- 这样即使用户已经创建了其他分组，也能确保默认分组存在

### 代码变更

**修改前：**
```typescript
function createDefaultGroup(): void {
  try {
    const groups = StoreService.getSessionGroups()
    if (groups.length === 0) {
      // 创建默认分组
      const defaultGroup = {
        id: CryptoService.generateId(),
        name: '默认分组',
        icon: 'folder',
        order: 0,
        depth: 1,
        parentId: null,
        createdAt: Date.now(),
        updatedAt: Date.now()
      }
      StoreService.addSessionGroup(defaultGroup)
      console.log('[Main] 创建默认分组:', defaultGroup.name)
    }
  } catch (error) {
    console.error('[Main] 创建默认分组失败:', error)
  }
}
```

**修改后：**
```typescript
function createDefaultGroup(): void {
  try {
    const groups = StoreService.getSessionGroups()
    // 检查是否已存在默认分组
    const hasDefaultGroup = groups.some(g => g.name === '默认分组')
    
    if (!hasDefaultGroup) {
      // 创建默认分组
      const defaultGroup = {
        id: CryptoService.generateId(),
        name: '默认分组',
        icon: 'folder',
        order: 0,
        depth: 1,
        parentId: null,
        createdAt: Date.now(),
        updatedAt: Date.now()
      }
      StoreService.addSessionGroup(defaultGroup)
      console.log('[Main] 创建默认分组:', defaultGroup.name)
    }
  } catch (error) {
    console.error('[Main] 创建默认分组失败:', error)
  }
}
```

## 验证结果

应用启动时控制台输出：`[Main] 创建默认分组：默认分组`

现在无论用户是否有其他分组，应用都会确保有一个"默认分组"存在，并且在目录树中正确显示。
