## 问题描述

### 现象
双击本地文件浏览器中的符号链接文件夹（如 `NetHood`、`Recent` 等）时：
1. 路径栏显示正确（更新为符号链接路径）
2. **但文件列表没有加载符号链接目标的内容**
3. 仍然显示当前目录的文件列表

### 影响范围
- Windows 系统下的符号链接文件夹
- 常见符号链接：`NetHood`、`Recent`、`SendTo`、`Templates` 等

### 复现步骤
1. 打开 SFTP 文件传输窗口
2. 在本地文件浏览器中定位到 `C:\Users\onesl\`
3. 双击符号链接文件夹 `NetHood`
4. **预期**：显示 NetHood 文件夹内容（3 个项目）
5. **实际**：路径变为 `C:\Users\onesl\NetHood`，但文件列表仍显示 80 个项目（父目录内容）

## 问题分析

### 根本原因
1. **isDirectory 判断错误**：
   - 代码使用 `dirent.isDirectory()` 判断是否为目录
   - 对于符号链接，该方法返回 `false`（因为符号链接本身不是目录）
   - 导致 `handleLocalDblClick` 中的 `if (item?.isDirectory)` 条件不成立

2. **即使修复 isDirectory，仍加载错误路径**：
   - 双击符号链接文件夹时，代码加载的是**符号链接本身的路径**
   - 而不是**符号链接指向的目标路径**
   - 例如：加载 `C:\Users\onesl\NetHood` 而不是 `C:\Users\onesl\AppData\Roaming\Microsoft\Windows\Network Shortcuts`

### 技术细节

#### 问题 1：isDirectory 判断
```typescript
// ❌ 错误代码
files.push({
  isDirectory: dirent.isDirectory(),  // 符号链接返回 false
  isSymbolicLink,
  // ...
})

// ✅ 正确代码
let isDirectory = dirent.isDirectory()
if (isSymbolicLink) {
  // 符号链接：使用 stats（跟随链接后的属性）判断是否为目录
  isDirectory = stats.isDirectory()
}
```

#### 问题 2：加载路径错误
```typescript
// ❌ 错误代码
if (item?.isDirectory) {
  state.localPath = item.path  // 符号链接路径
  await loadLocalFiles(connectionId, drivesPath)
}

// ✅ 正确代码
if (item?.isDirectory) {
  // 如果是符号链接文件夹，跳转到目标路径
  const targetPath = item.isSymbolicLink && item.linkTarget 
    ? item.linkTarget 
    : item.path
  state.localPath = targetPath  // 目标路径
  await loadLocalFiles(connectionId, drivesPath)
}
```

## 修复方案

### 修复 1：正确判断符号链接的目录类型

**文件**：`src/main/ipc/sftp.ts`

```typescript
// 对于符号链接，需要根据目标判断类型（而不是符号链接本身）
let isDirectory = dirent.isDirectory()
if (isSymbolicLink) {
  // 符号链接：使用 stats（跟随链接后的属性）判断是否为目录
  isDirectory = stats.isDirectory()
  
  // 读取符号链接目标路径
  try {
    linkTarget = fs.readlinkSync(fullPath)
  } catch (error: any) {
    console.warn(`[本地] 无法读取符号链接目标：${fullPath}`, error.message)
  }
}

files.push({
  name: dirent.name,
  path: fullPath,
  isDirectory,  // ✅ 修复后的值
  isSymbolicLink,
  linkTarget,
  size: stats.size,
  modifyTime: stats.mtime
})
```

### 修复 2：双击时加载符号链接目标路径

**文件**：`src/renderer/src/stores/sftpBrowser.ts`

```typescript
async function handleLocalDblClick(
  connectionId: string, 
  event: MouseEvent, 
  drivesPath: string
): Promise<void> {
  const target = (event.target as HTMLElement).closest('.file-item')
  if (!target) {
    console.log('[sftpBrowser] handleLocalDblClick: 未找到 file-item')
    return
  }
  
  const path = (target as HTMLElement).dataset.path
  console.log('[sftpBrowser] handleLocalDblClick: 双击路径 =', path)
  
  const state = getState(connectionId).local
  const item = state.localFiles.find(f => f.path === path)
  
  console.log('[sftpBrowser] handleLocalDblClick: 找到的 item =', item)
  console.log('[sftpBrowser] handleLocalDblClick: isDirectory =', item?.isDirectory, 'isSymbolicLink =', item?.isSymbolicLink)
  
  if (item?.isDirectory) {
    // ✅ 如果是符号链接文件夹，跳转到目标路径
    const targetPath = item.isSymbolicLink && item.linkTarget 
      ? item.linkTarget 
      : item.path
    console.log('[sftpBrowser] handleLocalDblClick: 进入目录', targetPath, 
      item.isSymbolicLink ? `(符号链接目标：${item.linkTarget})` : '')
    state.localPath = targetPath
    await loadLocalFiles(connectionId, drivesPath)
    console.log('[sftpBrowser] handleLocalDblClick: 加载完成，文件数量 =', state.localFileCount)
  } else {
    console.log('[sftpBrowser] handleLocalDblClick: 不是目录，不处理')
  }
}
```

### 修复 3：SftpLocal.vue 异步调用

**文件**：`src/renderer/src/components/terminal/sftp/SftpLocal.vue`

```typescript
async function handleDblClick(event: MouseEvent): Promise<void> {
```
