# BUG-050: SFTP 删除进度只有 0% 和 100%

## 基本信息
- **编号**: BUG-050
- **标题**: SFTP 删除大目录时，父文件夹长时间卡在 0%，然后突然跳到 100%
- **发现日期**: 2026-04-25
- **状态**: 已修复
- **严重程度**: 低（功能正常，用户体验差）
- **影响模块**: SFTP 删除功能
- **来源文档**: [sftp-logic-correctness.md#问题7](../../src/main/services/__problem__/sftp-logic-correctness.md)

## 问题描述

删除包含多个文件的目录时，父文件夹节点的进度显示只有两个状态：
1. 开始删除 → **0%**
2. 所有子项删完 + rmdir → **100%**

对于大目录（>50 个文件），父文件夹会**长时间卡在 0%**，给用户造成"卡死"的错觉。

### 错误现象

1. 用户选择删除包含 100 个文件的远程目录
2. 父文件夹显示 `████████░░░░░░░░░░ 0%`
3. 子文件逐个被删除（每个子项有自己的 0%→100%）
4. 父文件夹**始终停在 0%**，直到最后一个子项完成
5. 最后突然跳到 `█████████████████ 100%`

### 根因分析

**问题代码** ([sftp.ts deleteFile](../../src/main/services/sftp.ts))：

```typescript
// 目录删除流程
if (onProgress) {
  onProgress(0, 0, taskId, node)     // ← 开始：0%
}

// 循环删除子项...
for (const entry of entries) {
  await this.deleteFile(taskId, childNode, onProgress)
  // ← 每个子项完成后没有上报父节点中间进度！
}

// 全部完成
if (onProgress) {
  onProgress(0, node.size || 0, taskId, node)   // ← 结束：100%（唯一一次更新）
}
```

**进度时间线对比**：

| 时间 | 子项进度 | 父文件夹进度（修复前） | 父文件夹进度（修复后） |
|------|----------|----------------------|----------------------|
| T0 | - | 0% | 0% |
| T1 | 文件1: 100% | **0%** ❌ | 25% ✅ |
| T2 | 文件2: 100% | **0%** ❌ | 50% ✅ |
| T3 | 文件3: 100% | **0%** ❌ | 75% ✅ |
| T4 | 文件4: 100% | **0%** ❌ | 99% ✅ |
| T5 | rmdir 完成 | **100%** ❌ 突跳 | 100% ✅ |

## 修复方案

在每个子项删除完成后，计算并上报父节点中间进度：

```typescript
// 过滤有效子项（排除 . 和 ..）
const validEntries = entries.filter(e => e.filename !== '.' && e.filename !== '..')
const totalChildren = validEntries.length

for (let i = 0; i < validEntries.length; i++) {
  // ... 删除子项逻辑 ...

  // 每删除完一个子项，上报父节点中间进度
  if (onProgress && totalChildren > 0 && node.size) {
    const completedRatio = (i + 1) / totalChildren
    const intermediateBytes = Math.floor(node.size * completedRatio)
    onProgress(0, intermediateBytes, taskId, node)
  }
}
```

**进度计算公式**:
```
intermediateBytes = floor(node.size × (已完成子项数 / 总子项数))
```

前端根据此值计算百分比：`progress = transferredBytes / size * 100`

## 修改文件

- [sftp.ts](../../src/main/services/sftp.ts) - `deleteFile` 方法，在目录子项循环中添加中间进度上报

## 测试验证

1. 删除单个小文件 → 验证 0%→100% 正常（无中间态）
2. 删除包含 4 个文件的目录 → 验证父文件夹逐步推进：25%→50%→75%→100%
3. 删除包含 100+ 文件的目录 → 验证不再卡在 0%
4. 删除空目录 → 验证直接 0%→100%（无循环，不触发中间进度）
